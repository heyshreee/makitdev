01 / About

A small org with a narrow brief.

makitdev is an open source organization focused on building practical software and sharing it openly. We experiment with ideas, build useful tools, and release software that others can inspect, use, modify, and improve.

The work is intentionally small. A tool should solve one problem well, stay readable, and be easy to maintain. No unnecessary dependencies, no sprawling frameworks.

Focus
Developer tools, security, web infrastructure, and experiments.
Source
Public repositories, public issues, public discussions.
License

03 / How it works

From annoyance to release.

The process is deliberately short. The hard part is choosing the right problem.

01

Pick one problem.

Start with something you hit yourself. Write down the smallest version that would fix it.

02

Ship the smallest useful version.

A working v0.1 beats a perfect plan. Cut everything that does not help the first user.

03

Open it and keep improving.

Publish the source, the issues, and the next change. Feedback becomes the roadmap.

05 / Questions

Answers before you ask.

The short version of how makitdev works. If your question is not here, open a discussion on GitHub.

Open a discussion
What is makitdev?

makitdev is an open source organization that builds small, practical developer and security tools. Everything is published on GitHub.

Who is makitdev for?

Developers, security researchers, and curious builders who prefer tools they can read and change.

Are the projects free to use?

Yes. The source is public. Each repository carries its own license, so check the license file before you reuse it.

Can I use the code at work?

Many repositories use permissive licenses such as MIT or Apache 2.0. Read the license in the repository you want to use. It is the authority.

How do I contribute?

Open an issue, start a discussion, or send a pull request. Read CONTRIBUTING.md first so the change fits the project.

Do you accept feature requests?

Yes. Open an issue with the problem you want solved and the outcome you expect. Small, specific requests are easiest to act on.

How are projects maintained?

Projects that attract use grow documentation, tests, and a clear release path. Experiments may stay small or be archived.

How do I report a security issue?

Do not open a public issue for a vulnerability. Open a private security advisory on the affected repository, or contact the maintainer through their GitHub profile.

Do I need a GitHub account?

You need a GitHub account to open issues or pull requests. Reading the code and using the releases does not require one.

Where does the live data come from?

Repository and contributor data is read from the public GitHub API in your browser. If the API is unavailable, the page links to the organization page on GitHub.
